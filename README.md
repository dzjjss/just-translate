# Just Translate

只做翻译。不做单词本、不做 TTS、不做语言学习 —— 名字就是范围声明。
自带模型的沉浸式双语网页翻译，译文插在原文下面，原文一个字都不改。

> 内部的 DOM 类名、data 属性和 CSS 变量仍然是 `byom-` 前缀（bring your own model）。
> 改名不动它，是为了不破坏已有用户的存储数据，也不想为一次更名去动提取器和渲染层的契约。

- **BYO API**：九家预设 + 任意 OpenAI 兼容端点，每家一份 Key 并存，切换不丢。Key 在本地，不经过任何第三方服务
- **页面语境**：技术文档、论文、新闻、论坛各用各的翻译指令；翻译前整页只读一次，得到静态术语与歧义约束
- **语境可控**：普通页面无需人工干预；有特殊要求时再到「页面规则」补背景、固定术语或站点规则
- **任务优先 UI**：打开面板先看到目标语言、显示方式和「翻译当前页面」；模型、外观、规则与工具按使用频率逐级后退
- **语义一致性观测**：默认开启；只记录 occurrence、alignment 与 FIXED / STABLE / UNKNOWN，不修改译文
- **术语分权**：用户明确锁定的术语才是硬约束；自动预检只产生未验证的软建议，局部语义与语法角色可以覆盖
- **整页优先**：默认在 12,000 源字符、80 个正文单元以内一次提交全文，让模型直接利用跨段上下文；任一项超限自动分块，也可手动关闭
- **视口优先分块**：进入分块路径后，视口附近的段落先出队，滚动时优先级随之更新；无限滚动、SPA 重绘自动跟进
- **跨批先例 Beta**：仅在精确局部触发器重复时向后续批次提供旧译法；与观测分开，默认关闭
- **页面入口常驻**：普通 HTTP/HTTPS 页面静态注入轻量 content loader，让悬浮球能稳定出现；API 域名权限仍只在实际调用时按需申请

## 安装

```
chrome://extensions/  →  开发者模式  →  加载已解压的扩展程序  →  选择本文件夹
```

填好 API 地址、Key、模型，点「翻译当前页面」。第一次会弹一次权限请求，只针对你填的 API 域名。

| 快捷键 | 作用 |
| --- | --- |
| `Alt+T` | 打开面板 |
| `Alt+Shift+T` | 翻译 / 停止当前页 |
| `Alt+Shift+O` | 显示 / 隐藏译文 |
| 双击某条译文 | 只重翻这一段（绕过缓存） |

数据流：

```
页面 DOM
   │  extractor  →  单元 { id, 锚点, 插入方式, 原文, hash }
   │  chunker    →  按字符预算成批
   ▼
content  ──TRANSLATE_CHUNK──▶  background
   │        只发原文 + 页面语境        │  缓存命中 → 直接回
   │        永远拿不到 API Key         │  未命中 → prompt → provider → 对齐 → 写缓存
   ◀──────── { i, t } ────────────────┘
   │  renderer   →  在原文旁插入译文节点
```

## 三个设计决策

**1. 页面侧不接触 API Key。** content script 只发原文和页面语境，网络请求全部在 service worker。这不是洁癖：content script 与页面共享 DOM，一旦把 Key 或目标 URL 交给它，攻击面就从"我的代码"扩大到"我访问的所有网页"。

**2. 译文是新节点，原文不动。** 因此提取器判断失误的最坏后果只是多一行没用的译文，而不是页面被改坏。这条约束反过来简化了很多事：行内 `<code>`、`<a>` 的内容可以直接混进原文送给模型，不需要占位符保护和还原。

**3. 只按“所有权”拆，不按行数拆。** extractor 仍然保持一个文件，因为 DOM block abstraction
还要靠真实网页验证；但跨页面生命周期、调度、运行时配置、缓存契约已经有稳定边界，就必须各有
一个 owner。目录变多本身不是模块化，关键是同一个状态不能再被几个控制器一起改。

## 提取规则（跑不通的时候先看这里）

以「叶子块」为单位，块内混排的连续行内内容各自成一个 run。跳过标签分三类，混为一谈就会出事：

| 类别 | 例子 | 行为 |
| --- | --- | --- |
| KEEP | `code` `kbd` `samp` `var` | 文字留在句子里，不打断 |
| DROP | `script` `svg` `input` `select` | 文字不进正文，也不打断句子 |
| CUT | `pre` `iframe` | 打断段落，且不递归进去 |

行内标签只说明标签是行内的，不说明内容是行内的。`<a>` 里裹着整块卡片时（Google 搜索结果就是这样）
必须按块级递归，否则标题、站点名、网址会被 `textContent` 揉成一段。

另外会跳过：`.notranslate`、`translate="no"`、`aria-hidden="true"`、`contenteditable`、
`checkVisibility()` 为假的元素、纯数字 / 纯符号 / 纯 URL、已经是目标语言的段落（中日文按字符占比判定），
以及两类"翻了也是浪费"的内容：

- 单词条目（`skipSingleToken`，默认开）：用户名、品牌、标签碎片。标题和以句末标点收尾的短句除外，
  所以 `<h2>Introduction</h2>` 和 `<p>Yes.</p>` 仍然会翻。
- 放不下译文的容器（`skipTightLayout`，默认开）：`white-space:nowrap`、`text-overflow:ellipsis`、
  `-webkit-line-clamp`、已经在裁剪内容的 `overflow:hidden`，以及 flex/grid 子项、固定/吸顶容器、
  导航页眉页脚里的短文本。这类判断天生是启发式的，会有误判，逃生口是设置里的「跳过选择器」。

去重靠译文节点自己：同一段原文的 hash 没变就跳过，变了就复用旧节点重译。所以对同一页面反复扫描是安全且收敛的 —— 动态内容就靠这一点。

```bash
npm install
npm run check      # lint + 四个测试套件
```

**为什么有 lint。**一次「把预检 prompt 改成 YAML」的字符串替换静默失败，而 README 和测试
都当它成功了 —— 「页面原则」这个功能在三个版本里从未真正生效过。同一轮里还留下两处重复
对象键、一个未使用的 import，以及一个被误删的测试用例。这些全是机械检查一秒钟能抓的东西，
不该占用判断力。所以规则集刻意保持小：只拦「改动没落地」和「改完留残渣」，不做风格审美。

同一件事的另一半教训：当时的测试断言打在 `parsePreflightProfile` 上（解析器能不能吃 YAML），
而不是 `buildPreflightMessages` 上（prompt 到底要求模型输出什么）。**断言要打在契约那一侧。**

- `test/architecture.test.mjs` — 依赖方向、循环依赖、调度状态所有权。防止以后重构又把职责塞回 `main.js`
- `test/core.test.mjs` — PageSession / Scheduler / RuntimeContract / PageContext 的纯逻辑竞态测试，不依赖 DOM
- `test/cache.test.mjs` — 纯译文缓存：端点/模型/prompt 指纹隔离与命中策略
- `test/extractor.test.mjs` — DOM 提取、渲染、分批、摘要、漂移检测、规则解析、悬浮球
- `test/content.test.mjs` — 内容脚本整体在 jsdom 里跑起来：预检闸门时序、画像生命周期、
  SPA 换页、清除后重来。时序类 bug 只有这样才抓得到
- `test/popup.test.mjs` — 面板连同 HTML 真实加载并驱动：表单回填、LIVE/TRANSACTIONAL 设置生命周期、
  服务商 draft 与 Key 隔离、规则转换、试译台。`node --check` 抓不到 ReferenceError 和绑错的 id
- `test/settings.test.mjs` — 设置迁移。改默认值救不了老用户：读取是
  `{ ...DEFAULT_SETTINGS, ...stored }`，只要任意设置被持久化，已有字段就可能覆盖新默认；
  之后改常量对老用户未必生效。默认值的变更必须走 schema 版本号，且迁移要幂等 ——
  否则用户手动关掉的开关会被反复打开

## 翻译范围：正文优先

先探测正文根（`main` → `[role=main]` → `#mw-content-text .mw-parser-output` → `article`
→ `#content` → `.markdown-body` …），只扫描根内部；根内再排除目录、侧栏、编辑链接这类附属区块。
探测不到或候选文本量占全页不足两成时退回全页 —— 探测失败不该导致什么都不翻。

**语义标签靠不住，所以还有一条链接密度判断。**ArchWiki 的顶栏是
`<div id="archnavbar"><ul id="archnavbarlist">`，既没有 `<nav>` 也没有 `role="navigation"`，
任何基于语义容器的规则都抓不住它。链接密度看的是事实：一个容器里几乎所有文本都在
`<a>` 里、且每条都短，那就是导航，不管它用什么标签。

在此之前"正文优先"只是 README 里的一个名字，实际行为是一堆基于布局的启发式补丁，
碰上不用语义标签的站点会集体失效 —— 表现就是整页导航、目录、外观面板全被翻译。

完全模式（连导航一起翻）没有实现，卡点不在范围判定而在渲染：界面文本插块级兄弟节点必然
撑坏横向布局。它的前置条件是给 ui 角色单独做一套不占布局的渲染（悬停浮层），
在那之前提供开关只会让人打开一个会毁掉页面的选项。

## 翻译预检：一次读整页，软建议全程复用

「预检本页」把正文拼成纯文本摘要（保留 `#` 层级与 `-` 列表，去 URL 去重复，
超预算先按结构采样——优先标题、每节留前两段——并有最终字符硬上限；极端的超长单节点会在
预算边界截断），一次调用产出文档画像。自动画像只负责三类软信息：领域提示、术语建议、风险词。
**它不能自行创建 principle / hard / keep rule**。

这是刻意的权限边界。一次随机模型预检不应该因为把 `Wi-Fi`、`Settings` 或 `Insights` 猜成术语，
就获得改变整篇译文的强制权。自动术语映射进入独立的 `SUGGESTED` prompt block，只在当前 occurrence
语义与语法角色相符时作为软提示；用户在页面规则里明确写下的「锁定」才是 `ENFORCED`。

当前 trust 分四档：

- `OBSERVED`：只观测到的 occurrence，不影响后文
- `SUGGESTED`：自动预检等未验证提示，允许局部语境覆盖
- `AUTO`：高置信 identifier 等程序可确定证据
- `ENFORCED`：用户明确 hard rule，必须执行

页面语境默认只给摘要，完整规则树按需展开；需要人工覆盖时点「调整页面规则」，也可以把自动建议复制进
规则框再编辑。系统不会因为画像短、没有术语建议或只有风险词就催用户校准。

**同一 URL 的预检结果会复用。**模型、观测/实验开关或重翻导致 PageSession 重建时，默认继续使用同一份
preflight snapshot；只有显式「重新读取」才重新调用模型。snapshot 会记录 hash、创建时间和是否复用，
用于严格 A/B 时固定规则基线，避免比较的其实是两次不同的预检输出。

**预检直接吐 YAML。**新契约只允许 `领域 / 优先 / 风险词`。即使旧模型、旧缓存或旧页面状态仍返回
`principle / hard / keep`，进入正式翻译前也会清空；其中旧 `hard` 只降级为 `preferred` suggestion。
用户规则不走这个降权路径，因此人工写下的页面原则、锁定项和不翻项仍然有效。

**闸门式，不是先后式。**首次没有可复用 snapshot 时，翻译请求会等预检完成后再放行，避免前几批先于页面画像
各翻各的。自动预检默认开启；不想要可以在高级设置里关闭。

## 整页优先与自动分块

「优先整页翻译」现在是默认调度策略，不再是无条件尝试的 Beta。提取器仍按 DOM 单元保留每段的 `id`、
边界和文档顺序；首轮正文若同时满足 **不超过 12,000 个源字符、且不超过 80 个单元**，调度器就把完整
扫描快照放进一次正式翻译请求。这样模型能直接看到跨段指代、人物关系、语体和同词不同义，通常也比重复发送
批次级 prompt 更省 token。

任一门槛超限就自动进入原有分块路径；关闭开关则始终分块。门槛是保守、确定、可测试的工程值，不假装代表
所有模型的真实上下文能力：服务商仍可能有更低的输入、输出或超时限制。三个边界是：

- 自动预检仍是独立的一次短请求；「整页」只指正式翻译请求。
- 无限滚动或 SPA 后来新增的正文不能冒充首轮全文，会按分块路径增量处理。
- 整页缓存以“完整有序页面快照 + 单元位置”为身份。只有 100% 命中才复用；部分命中一律忽略并重新发送全文，
  完整翻译成功后才写入全页结果。模型漏回 id 时仍沿用漏项二分补偿。

观测数据会记录 `translationMode / modeReason / sourceChars / unitCount / translateRequestCount /
splitRetryCount / wholePageCacheHit`，方便比较整页和分块的质量与成本。

## 页面内界面：Shadow DOM，不是裸 div

悬浮球和状态条住在 Shadow DOM 里（`ui-host.js` + `ui-css.js`），译文节点仍然留在正常 DOM。
这是两类东西，处理方式刚好相反：译文要融进页面、继承排版、能被 Ctrl+F 搜到；
界面要与页面互不干扰。

裸 div 挂 body 有五个真实隐患，宿主模块逐条处理：

| 隐患 | 处理 |
| --- | --- |
| 站点 CSS 用更高优先级或 `!important` 打穿我们的样式 | Shadow DOM 隔离，`:host { all: initial }` 切断继承 |
| body 上有 `transform`/`filter` 时 `position: fixed` 会以它为参照系 | 挂到 `documentElement` |
| 单页应用清空 body 会把我们一起清掉 | MutationObserver 观察脱离并自动重挂 |
| 站点自己的浮层把 z-index 顶到最大 | 我们也用最大值 |
| 站内元素进入全屏后普通层的 fixed 元素不可见 | 监听 `fullscreenchange` 跟着搬进全屏元素 |

另外 shadow 内部一律用 px 不用 rem/em：不少站点把 `html` 的 `font-size` 改成 62.5%，
rem 在 shadow 里照样会被带跑。

**悬浮球的全部逻辑收在 `float-widget.js` 一个文件里**：挂载、宿主、拖动、菜单、状态、
失败提示、自愈，以及"该不该显示"的判断本身。对外只有一个幂等的 `sync(config, handlers)`。

之前它散在三处（fab 管交互、ui-host 管重挂、main 管显示与否），出了两类只有组合起来
才会犯的病：自动重挂只是把节点 append 回去，绕过了事件绑定，表现为「球在但点不动」；
`syncFab` 以前依赖一个跨生命周期共享的配置对象，而配置来自三条时序不同的路径，某些进入方式下它还是 null，
球就不出现。现在自愈的判据是「节点在且 shadow 里有按钮」，不健康一律整体重建 ——
补挂救不回一个空壳。

悬浮球可以上下拖动，位置记住 —— 固定档位总会在某些站点正好压住人家自己的按钮。
拖动位置由后台代写，因为 `storage` 已经收紧到可信上下文，内容脚本没有写权限。

## 悬浮球与面板

- **设置有生命周期，不再共用全局「应用」**：显示、外观、悬浮球、普通开关和轻量性能参数改动即保存；
  Provider / API / Key / Model 与长文本页面规则分别作为事务配置块，只有它们保留「应用模型设置 / 应用规则」。
- **主流程不会被应用按钮卡住**：直接点「翻译当前页面」会自动提交尚未应用的模型/规则 draft；
  两个应用按钮只用于“保存配置但现在不翻”。测试连接、拉取模型和临时翻译可直接使用当前 model draft。
- **LIVE 设置即同步**：content script 由 manifest 在普通网页上静态注入；已注入页面即时接收 RuntimeConfig，
  打开悬浮球时会在当前页尚未注入的情况下主动走 `SYNC_ON_TAB` 兜底。
- **悬浮球默认开启**：位置可选右下/右中/右上。点一下按状态执行翻译 / 停止 / 重翻，长按或右键弹出小菜单
  （翻译 / 刷新页面语境 / 清除）。翻译进行中有呼吸动画，失败会在球体旁给出短提示。
- **面板按任务层级组织**：当前页面是唯一一级主任务；页面语境、显示与外观是直接相关的次级信息；模型与 API
  首次配置时自动前置，配置完成后退位；设置使用一级 Tab，不再嵌套多层折叠。

## 显示与导出

- **显示方式是当前任务选项，不是事后操作**：它和目标语言一起放在「当前页面」卡片里，先选好再翻。
  页面上的切换按钮和快捷键同样是在改这个设置，所以切一次下一页打开还是这个模式。
- 三态：双语 / 仅译文 / 仅原文。「仅译文」按单元类型分两种做法：元素级单元直接藏掉源元素；
  译文在元素内部的（列表项、单元格、引用块）藏容器会把译文一起藏掉，改为把容器字号压成 0
  再用 `--byom-own-size` 把译文字号还原 —— 裸文本节点选不中，字号是唯一能一并收拾掉它们的办法。
  只有混排段落里的游离文本（`<div>文字<pre>…</pre>文字</div>` 这种）仍然无解，那类保持双语。
- 「重翻」先清除再翻译；「重翻⟳」额外绕过缓存，用来验证改了指令或画像之后的效果。
- 连续三次同一错误自动熔断停止——Key 错了不该把页面糊满红字还继续烧钱。
- 「导出对照 MD」输出全页双语 Markdown。
- 清理分两个按钮：「清缓存与本页画像」把后台缓存和当前页预检画像一起清空；
  「仅清缓存」只动后台缓存。
- 完成后状态条显示 token 用量与缓存命中段数。

## 多义词：边界与人工复核

多义词在同一篇文本中连续出现不同含义时容易出错，且这类错误往往读起来很通顺，不易察觉。
涉及专业、法律、医疗等场景请务必人工复核。我们的机制（画像风险词、译后漂移检测）能压低
和暴露这类问题，但受限于分批翻译，无法完全消除。译后检测也有已知盲区：中文没有词边界，
"小部件工具包"这类加字变体会被放过，能抓到的是完全换了译法的硬漂移。

## 悬浮球什么时候会出现

悬浮球是页面级主入口，因此普通 `http/https` 页面由 manifest 静态注入 content script。
`floatButton` 默认开启时，新页面加载完成后会直接自举并显示悬浮球，不需要先打开面板、翻译一次或刷新。
关闭 `floatButton` 只隐藏悬浮球，不影响翻译主链；Chrome 自身限制的页面（如 `chrome://`、商店页面）仍不会注入。

这会让安装权限提示包含网页读取/修改能力，这是常驻页面入口的明确产品取舍。BYO API 的跨域访问仍走
`optional_host_permissions` 按实际 API origin 单独授权；静态 content script 权限不替代后台 API host permission。

## 面板结构：按使用流程排，而不是按内部模块排

日常路径是：打开网页 → 选目标语言/显示方式 → 翻译 → 必要时看页面语境或补规则。因此主按钮、目标语言和
双语/仅译文放在第一张「当前页面」卡片里，其他设置按频率逐级后退。

| 区 | 什么时候用 | 内容 |
| --- | --- | --- |
| 当前页面 | 每次 | 目标语言、显示方式、翻译/进度、当前状态 |
| 页面语境 | 偶尔看 | 自动读取到的领域、术语建议、风险词；完整规则树按需展开 |
| 语义一致性观测 | 默认开启 | 变体与对齐摘要、诊断数据复制；不修改译文 |
| 设置 · 模型 | 初次/换模型 | 协议、地址、Key、模型 |
| 设置 · 外观 | 偶尔改 | 译文标记、颜色、字体、悬浮球 |
| 设置 · 页面规则 | 有特殊要求时 | 本页背景、精确规则、站点规则、全局偏好 |
| 设置 · 高级 | 排障/低频 | 临时翻译、提取与性能、测试连接、导出、缓存和 debug |

页面语境和页面规则继续读写分离，但不再把“自动结果很短”表现成错误。fallback 到通用页面、没有风险词、
没有自动术语建议都很正常；「调整页面规则」始终只是一个普通次级动作。真正的 warning 只留给配置错误、请求失败、
页面不可注入等需要用户处理的情况。

**三个人工输入口的作用域仍然明确分开：**

| 入口 | 作用域 | 用途 |
| --- | --- | --- |
| 页面背景 | 本页 | 只有特殊背景时补一句自然语言说明 |
| 精确规则 | 本页 | 锁定/优先/风险词等明确约束 |
| 附加指令 | 全局 | 所有页面长期通用的偏好 |

性能参数、缓存、debug 和临时翻译不再和主任务抢一级视觉位置；功能保留在设置的「高级」一级 Tab。

v15.0 把面板基础字号、说明文字、输入框与开关的点击面积统一上调，并使用本机 UI 字体栈；设置齿轮改为固定
viewBox 的描边 SVG，不再受字体或缩放影响。API Key 旁新增显式「复制」按钮，复制当前输入框内容（包括尚未
应用的草稿），不会自动显示、记录或上传 Key。

## 临时翻译

手头有一段内容想翻，不必为它开一个网页。填进去、点一下，就翻这一段。

它带上本页当前的语境与规则，走的是和整页翻译完全相同的组装路径 ——
另起一套 prompt 会让"这里翻出来的和整页翻出来的不是一回事"。在页面上双击一条译文，
那段原文会自动带过来。每次都是一次真实调用，结果里报 token。

刻意不做对照、不做临时规则、不做"把规则并进去" —— 它的职责就是翻你给的这一段，多了没必要。

## Prompt 数据格式与语义一致性

发送给模型的页面信息、items、预检输入统一使用确定性的 **YAML 子集**；模型返回的翻译结果仍严格要求 JSON。前者适合结构化上下文，后者保留 `JSON.parse()` 的确定性。

**语义一致性观测默认开启，但不会改变译文。**它收集 occurrence、alignment、真实目标变体与样本，taxonomy v3 的语义结果只保留有可靠判据的 `FIXED / STABLE / UNKNOWN`；标题排版和章节号仍以 `STRUCTURAL` 形式类排除。旧版的 `contextual / compositional / polysemous / stylistic / properNameDrift` 汇总字段继续保留为兼容字段，便于历史数据横向比较。

观测层在比较目标变体前会做确定性的排版归一化：NFKC、空白整理、剥掉首尾成对引号/书名号；原始 `renderedRaw` 仍保留。因此 `设置 / “设置”` 不算术语漂移。普通 ALL CAPS 标题、章节号和罗马数字归 `STRUCTURAL`，不会因为长得像 `API / LTE` 就直接获得 FIXED 权限。

`sourceRoleShape` 与 `TARGET_VARIANT_CONTAINMENT` 不再参与语义分类。像 `battery → 电池 / 电`、`Learn → 了解 / 进一步了解`、`Martian → 火星人 / 火星` 都先留在 `UNKNOWN`，代码不再用局部词形或目标子串替代语义判断。

会修改 prompt 的 scoped memory 被拆成独立的「跨批先例注入」Beta，默认关闭。开启后仍不保存裸词 canonical，只保存 **带精确局部触发器的先例**：`battery power → 电量` 与 `Power Mode → 电源` 会生成不同 trigger；同一 trigger 自己出现多个目标变体时立即熔断。诊断数据除 hit/conflict 外，还记录 `precedentMatched / precedentDiverged / precedentUnaligned`：它们只表示“给过先例后实际 alignment 是否相同”，不冒充因果证明。

## 自然语言转规则

用自己的话写清楚这是什么页面，点「转成规则」，模型把它转成结构化文本：

```
原则: 命令与参数原样保留，说明性语气不做润色
领域: Wayland, Linux 图形栈
锁定:
  compositor: 合成器
优先:
  widget toolkit: 部件工具包
风险词:
  output: 指显示输出设备，不是输出结果
  stuttering: 画面卡顿掉帧，不是口吃
不翻: 命令, 路径, 环境变量
```

风险词那一档是这套设计的关键。给固定译法，义项判断错时会把错误钉死（`stuttering → 口吃` 就是这么来的）；
什么都不给，模型又会滑回词典默认义。**给义项、不给译法**是这两者之间唯一站得住的位置：
义项由领域定死，措辞仍然逐句由模型选。

领域行也不只是陈述。只写"领域是 Wayland"没有约束力，prompt 里跟着一句
"在这个领域内，词的领域义永远压过日常义，哪怕日常义读起来更顺"——这才是让领域起作用的部分。

**结果一定回填到可编辑的框里，不直接生效。**转换器本身也是模型调用，会读错、会漏、
会自作主张；不给人过目就等于把错误固化进之后的每一次请求。手改之后当场解析校验，
格式坏了立刻提示，而不是等翻译时静默失效。

四档的语义是刻意分开的：**锁定**不许因为语句流畅度而改；**优先**是倾向，允许语境覆盖；
**风险词**写义项不写译法；
**不翻**是整类内容。

用户规则与自动预检严格分权：**用户写的永远压过模型猜的**。自动预检最多提供软建议；用户锁定项会从自动 preferred/risky 冲突位置移除，并以 ENFORCED 权限进入正式规则。规则可以随站点规则一起固定，下次打开同一站点直接生效。

也可以完全不用转换器，直接手写上面那种格式。解析容忍缩进不齐、冒号后缺空格、
中英文分隔符混用、以及模型偶尔直接吐 JSON。

## 语境：自动识别之外的三层控制

纯自动识别一定会有认错的时候，所以判定结果必须可见、可改、可固定：

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 看得见 | 状态条与面板都显示「识别为 X，依据：Y」 | 依据有四种：本站规则、域名匹配、页面结构、默认兜底。看到「默认兜底」就说明它其实没认出来 |
| 当场改 | 状态条上的语境下拉 | 只影响当前页面，对后续段落立即生效 |
| 固定住 | 面板的「固定到本站」 | 把语境和页面背景钉在这个域名上，下次打开直接生效 |

站点规则还可以勾「打开本站时自动翻译」。配合常驻悬浮球，常读的站点就完全不用再点任何东西。

「页面背景」是一段人工写的说明。面板里给了五个模板（法律条文、技术文档、学术论文、新闻报道、
产品页面），点一下填进去再按实际页面改写；输入框上方的角标会显示这段话当前管哪儿 ——
「仅本页」还是「已固定 · 某域名」。
它进入 system prompt 的稳定段，也计入缓存指纹 —— 改了背景不会再吃到旧译文。
上限 500 字：它随每一批发送，写长了成本会被放大 batch 倍。

## 译文呈现：差异化与层级是两条正交规则

- 默认视觉改为 **Sunset Orange**：交互强调色使用 `#F2783C`，长文译文不用高饱和橙，而使用更耐读的 Sunset Ink（浅色页 `#9A4F2D`，深色页 `#F2A06B`）。旧版本仍保持默认紫色且用户没改过配色时会自动迁移；自定义过颜色的不覆盖。
- 字族由译文统一指定（默认中文字体栈，可在面板改）。这是「差异化」：一眼分得清哪句是译文。
  之前版本靠 `font-family: inherit` 加上西文字体缺中文字形时的回退，效果是撞出来的，换个站点就消失。
- 字号与字重由源元素派生。这是「层级」：标题的译文仍然像标题。`attach` 时把源标题字号写进
  `--byom-src-size`，CSS 用 `clamp()` 收在 15px–34px 之间，既保留层级也不喧宾夺主。
- 译文字体只增加一层亚像素轮廓阴影：浅色页用浅边、深色页用暗边，让暖橙字色在复杂背景上
  仍保持轮廓。它只作用于已完成译文；不使用会改变中文字重的 `text-stroke`，高对比/强制配色
  模式下自动关闭，主题切换只更新根节点变量。
- 标记样式四选一：左边线 / 虚线下划线 / 淡背景 / 无标记，切换只改 `<html>` 上的属性。
- 等待中的段落显示一个转圈，不显示"翻译中"字样：文字会被当成译文本身读，
  还会占掉和真实译文相近的宽度，回填时整段跳一下。`prefers-reduced-motion` 下退回静态省略号。

验收标准是两句话：同一页面里译文之间要能分出标题和正文，译文和原文之间要能一眼分出哪句是译的。

## 范围声明

只做翻译。视频字幕、TTS 朗读、单词本、PDF、漫画、电子书一概不做 —— 不是做不了，
是每加一样都会稀释掉唯一值得打磨的东西：正文翻译的准确度和可控性。

## 填 Key 不用翻文档

每家服务商都带上了 Key 格式、控制台链接、模型名示例：

- **地址粘错自动纠**：从文档里整条复制 `https://api.deepseek.com/chat/completions` 过来，
  会被收拾成 `https://api.deepseek.com` 并告诉你改了什么。漏协议头、带引号逗号、
  多余尾斜杠、官方 base 该带 `/v1` 而漏了，都一并处理；本地地址不会被强行加 https。
- **Key 格式软校验**：前缀不符或夹带空格会提示，但绝不拦截 —— 各家随时可能换前缀，
  硬拦会把能用的 Key 挡在外面。
- **模型点一下拉取**：`GET /models` 把这家当前可用的模型抓回来填进候选，
  嵌入 / 语音 / 图像类自动过滤掉。两条线协议都支持。

## 缓存

缓存只做一件事：**相同翻译语义 + 相同原文，直接复用译文。**它不参与术语生命周期，
不恢复页面状态，也不向下一批传递任何东西。

- key = `providerId + endpoint + model + promptFingerprint + source text`。
- `promptFingerprint` 已包含目标语言、preset、页面背景、预检/用户规则、自定义 prompt 与实际 sampling 行为。
- 整页模式使用独立 prompt 身份；缓存只在完整有序页面快照 100% 命中时复用，部分命中仍发送全文。
- 条目只保存 `{ t, ts }`。旧条目即使还带历史 `g` 字段也只读取译文，不恢复任何术语状态。
- 同一个模型名指向官方端点、中转站或自建网关时，endpoint 不同，因此不会跨服务误吃缓存。

## 配置热更新分四类

改颜色和改目标语言不是同一种变化，一锅端会出事：目标语言从中文改成英语之后，
页面上旧的中文画像还挂着，下一批模型收到的是「Translate into English」配上
「security interest => 担保权益」，一个自相矛盾的 prompt。

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 呈现 | 字色、标记样式、悬浮球 | 即时应用，不碰已有译文 |
| 调度 | 每批字符 | 下一批自然生效 |
| 提取 | 正文优先、过滤噪音、跳过选择器 | 重新扫描 |
| 观测 | 语义一致性观测 | 建立新 PageSession 清空统计，不改变 prompt |
| 语义 | 模型 / API 端点 / 自定义 prompt / 语境 / 页面背景 / 规则 / 自动预检 / 目标语言 / 整页优先 / 跨批先例 Beta | 建立全新 PageSession，整页重来，旧请求结果一律不能写回 |

页面侧不需要、也不应该知道模型名、API 地址或自定义 prompt 的内容。后台把所有会改变翻译语义的
设置压成一个 `semanticRevision` 下发；revision 一变就开新 PageSession。以后新增模型参数时，
不用再同时修改 content 的字段表、状态清理和缓存分支。

## 服务商与 Key

**全新安装默认使用 DeepSeek 官方省钱档**（`https://api.deepseek.com` + `deepseek-v4-flash`）。这只是 fresh default：升级不会静默切换已有用户当前的 provider、endpoint 或 model。

预设九家：OpenAI 通用、DeepSeek 官方省钱档、Anthropic、Google Gemini（OpenAI 兼容层）、
Azure OpenAI、SiliconFlow、OpenRouter 免费档、本地 Ollama / LM Studio、以及任意自定义端点。

**每家一份账户，切换不丢 Key。**顶层的地址/Key/模型三件套是"当前生效"的那份，
同时按服务商 id 落一份到 `accounts` 里；切换服务商时先存回原来那家，再读出目标那家。
之前是扁平的一份配置，切一次 DeepSeek 的 Key 就被覆盖了——这是日常使用里最烦人的坑。
面板里会列出哪几家已经配好 Key。

**认证方式抽象成 `auth` 字段**，所以接一家新服务商通常仍然只是加一条记录：

| auth | 位置 | 例子 |
| --- | --- | --- |
| `bearer` | `Authorization: Bearer <key>` | 绝大多数 |
| `api-key` | 自定义请求头 | Azure OpenAI |
| `query` | 查询串 `?key=` | 部分原生端点 |

Azure 还需要 `api-version` 查询参数，由 `extraQuery` 提供；地址填到部署名那一层，
模型名填部署名。OpenRouter 的免费模型必须带 `HTTP-Referer` 与 `X-Title` 两个头，
否则直接返回 402 且报错信息看不出原因，由 `extraHeaders` 提供。

Key 格式校验一直是软提示不拦截，这次派上了用场：Google 已把 Gemini 的 Key 从 `AIza…`
换成 `AQ.Ab…`，旧格式 2026 年 9 月起停用。校验规则已经放宽到两种都认，
但即使规则再次过时，你也照样能点翻译。

导出配置或分享设置前请自行移除 Key —— 我们不做云同步，Key 只在你本机的
`chrome.storage.local`，并且启动时已把访问级别收紧到可信上下文。

## DeepSeek 省钱档

全新安装会默认选中这一档；已有用户升级后保持原模型不变。面板里选「DeepSeek 官方 · 省钱档」会自动套用 `https://api.deepseek.com` 与 `deepseek-v4-flash`，
并在请求里带上 `thinking: {type:'disabled'}`。这一条很重要：DeepSeek 的思考模式默认开启，
CoT 会计进输出 token，而输出是最贵的一档；翻译用不到推理链，关掉能省几倍钱和延迟。
（顺带一提，思考模式下 `temperature` 是无效参数，不报错也不生效。）

省钱还有第二层：供应商按前缀命中缓存，缓存命中的输入价格比未命中低约两个数量级。
所以 `prompt/build.js` 里 system 的拼装顺序是刻意的——通用规则 → preset → 自定义指令（稳定）
→ 页面静态画像。把稳定内容排在前面，同一页后续批次、乃至同一 preset 的其他页面都能吃到供应商前缀缓存。
调整顺序前先想清楚这件事。

另外注意峰谷计价：峰时为 UTC 01:00-04:00 与 06:00-10:00，其余时段半价，
换算到北美东部就是晚上 9 点到午夜、以及凌晨 2 点到 6 点为峰时。价格随时可能变，以官方页面为准。

## 扩展点

**加供应商**：绝大多数情况只需在 `shared/provider-catalog.js` 的 `PROVIDER_PRESETS` 里加一条，
写清默认地址、默认模型和额外请求字段即可，不需要新文件：

```js
{
  id: 'deepseek',
  wire: 'openai',                                   // 复用现成的线协议
  defaultBase: 'https://api.deepseek.com',
  defaultModel: 'deepseek-v4-flash',
  extraBody: { thinking: { type: 'disabled' }, max_tokens: 8192 }
}
```

只有线协议真的不同（比如 Anthropic 的 `/v1/messages`）才需要新增一个 wire，实现
`complete({ base, apiKey, model, system, user, temperature, extraBody, signal }) → { text, usage }`
并在 `WIRES` 里注册。刻意不做第三层"统一适配层"——那会把这个项目变成 LiteLLM 的缩小版，
而事实是绝大多数供应商本来就说同一种协议。

**加页面语境**：在 `src/prompt/presets.js` 加一条 guidance，`classify.js` 里加域名或结构特征。
prompt 的输出合同由 `build.js` 统一维护，preset 只负责领域差异。

**站点规则**：设置里的 `siteRules`，形如 `[{ host: 'arxiv.org', presetId: 'academic' }]`，优先级高于自动识别。

**改坏了怎么办**：`PROMPT_VERSION`（`shared/constants.js`）加一，旧缓存自然失效。

## 权限

| 权限 | 用途 |
| --- | --- |
| `content_scripts.matches` | 在普通 HTTP/HTTPS 页面静态拉起 loader，保证悬浮球作为主入口随页面出现；这会产生网页读取/修改权限提示 |
| `activeTab` + `scripting` | 只作当前页兜底：扩展刚更新但旧标签页没刷新、或用户把站点访问改成「点击时」时仍可手动注入 |
| `storage` | 设置与译文缓存。启动时调用 `setAccessLevel({accessLevel:'TRUSTED_CONTEXTS'})` 把 storage 对 content script 关掉，所以"API Key 不下页面"是能力边界，不只是代码约定 |
| `optional_host_permissions` | 运行时只申请你填的那一个 API 域名 |

service worker 的存活靠页面在翻译期间每 20 秒发一次心跳（消息会重置空闲计时器）。
全部翻完就停，有新内容再拉起；页面关闭或导航离开时，后台会按 tabId 中止这个页面名下
还在飞和还在排队的请求 —— BYO API 花的是你自己的钱。

## 已知边界

- 只处理主文档，`<iframe>` 内的内容不翻。
- `display` 被站点大改的 `div` / `span` 少数情况下会误判块级（只对 span / a / label 查计算样式，其余走标签表，这是性能取舍）。
- 只有显式开启「跨批先例注入」Beta 后，重复词才会在 `lemma + exact local trigger` 完全一致时复用本页先例；
  不会把一次 occurrence 的译法泛化成裸词全局映射，因此不同语境之间仍可能出现不同译法。
- 缓存上限 4000 条，按最后命中时间淘汰。
