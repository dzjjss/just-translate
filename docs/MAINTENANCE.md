# v0.17.7：轻量提示、维护排版与阅读导出

延续已交付的 v0.17.6；最初基准仍为用户上传的 v0.17.5，未使用旧仓库 16.0。前三项小工作已完成，剩余四项见 TODO。

## 反馈与排版

- 面板不再为反馈保留底部空间；内部滚动上限由 548px 恢复为 598px，含外边框仍不超过 600px。
- 右上角浮动提示随内容收窄。处理中/成功提示约 3.2–10 秒收起（依消息长度）；长操作的按钮反馈持续显示。悬停/聚焦暂停关闭，错误和警告持续到用户关闭或下次操作。
- 提示不抢焦点；关闭按钮可通过键盘使用，在提示内按 Escape 可关闭并返回原控件。旧提示定时器不能关闭新错误，较早请求不能覆盖新操作结果。
- 维护工具三个分组：阅读导出、缓存清理、问题诊断。数量在清理标题旁显示，不挤压按钮；日志技术/隐私详情折叠，仅折叠说明，不隐藏动作。
- 面板与页面工具统一小字尺度和文字对比度。保留已完成的纸色底、大标题宋体及单层轻阴影。译文取消 plain/UI 重复透明度衰减，弱化色 72% → 85%；不改用户自定义色值，不声称已解决宿主页面排版兼容。

## 导出

`markdown-export.js` 仅在导出时从当前单元和 DOM 派生格式，不修改页面、单元状态、Prompt 摘要或模型请求。

- 完成态、仍连接的译文按当前渲染树排序，动态插入、开放组件和插槽均适用。同一译文节点只导出一次。
- H1–H6 保留层级；图注/表题用独立斜体段落，避免以前的 heading 角色误判；多段列表不再重复生成编号，嵌套项和显式编号保留。
- 表格使用 GFM 行列，在同一单元格内以上下两段表示原文/译文。已导出行中的未翻译数字/标签保留原文；没有完成译文的整行不导出（表头除外）。合并格按位置展开，后续占位留空；不是 HTML rowspan/colspan 复刻。
- 明确导航、控件、工具栏与站点级页头页脚不输出；正文内部的页头、侧栏段落和参考链接文字仍保留。不会按文字长度粗暴删除正文。
- 原文和译文均按纯文本转义，不能注入 Markdown 链接、表格分隔符或 HTML。图片、链接目标、代码块原始格式和整页 HTML 归档不在本次导出范围。

## 验证与安装

- `npm run check`：lint 与原有 404 项回归通过；新增 8 项导出、3 项提示生命周期回归，合计 415 项逻辑/DOM 用例。

# v0.17.6：统一操作反馈

基准为用户上传的 `just-translate-v0.17.5.zip`，没有从旧仓库 16.0 合并代码。交付新版本 `just-translate-v0.17.6.zip`，原始基准包保留。本次没有修改翻译算法、缓存匹配、权限清单或模型请求内容。

## 行为

- 全部 `bindAction` 按钮通过 `createActionFeedback` 执行，点击同步进入忙碌态，保留权限/剪贴板的用户手势。反馈通过属性与伪元素绘制，不改写原按钮子节点，缓存计数和图标身份保持。
- 每个操作明确返回结果。失败和部分成功有不同提示；旧操作的回执不会覆盖新操作的结果。按钮结果保留 2.4 秒，当前完整结果保留在可见状态区。处理超过 12 秒提示仍在等待。
- 面板底部固定预留 50px；内部滚动区上限 548px，与边框合计仍为 600px。没有覆盖内容的悬浮提示。同步导航、标签、Key 显隐仍使用直接状态切换，无额外假加载。

- UI 超时只结束等待，不声称后台已取消，也不自动重发。保存超时或通道断开可能已经在后台生效，提示用户先确认结果再重试。晚回执不会进入已超时等待的成功处理分支。
- 悬浮菜单、悬浮主按钮、HUD 操作沿用相同状态颜色、等待线和文字。悬浮位置/显示偏好保存失败不再静默；界面切换本身仍立即生效。

# v0.17.4：开放组件中的正文（上一版记录）

基于已交付 v0.17.3 修复，直接交付 `just-translate-v0.17.4.zip`，未提交或推送。用户补充的 DevTools 截图选中了 `div.d2l-html-block-rendered`；[Brightspace 官方组件源码](https://github.com/BrightspaceUI/core/blob/main/components/html-block/html-block.js) 的默认渲染分支在 `this.shadowRoot` 中找到这个容器，再异步写入处理后的 HTML。旧提取器只走 light DOM，旧观察器只看 document.body，无法进入这个分支；只放宽标签选择器不能补齐。

截图、官方组件实现与本地失败夹具共同支持这个机制。没有取得登录后课程页的完整 DOM，因此不声称已在该账户的真实页面上验收，也不推断其他翻译扩展的内部实现。

## 修改与所有权

| 位置 | 变更 |
| --- | --- |
| dom-roots.js | 无保留状态的渲染子节点、跨根祖先与开放根遍历；slot 按实际投影读取，不重复发送未分配内容 |
| extractor.js | 原有叶子块与 run 规则进入开放组件；跨根保留正文/导航判断、明确跳过边界和插槽回填归属 |
| observer.js | 同一个 MutationObserver 监听 body 及当前开放根，防抖后重新绑定；同一 AbortController 清理根事件，stop 释放全部监听 |
| renderer.js / main.js | 跨根清除译文及漂移标记；双击通过 composedPath 定位原单元。会话、预检、缓存和调度流程继续消费相同 unit |
| shadow-styles.js / content.css | 按需读取包内 CSS，所有根共享一份 CSSStyleSheet；html 的属性和变量控制显示与配色，无每根模式副本 |

组件内部文字变化、重绘、插槽变化和外层 DOM 变化都会触发发现。点击与返回标签页也会补查延迟附加的根。没有轮询、attachShadow 原型补丁或额外根登记表。完全静默地给旧宿主附加新根时，仍需等下一次交互或扫描；iframe、封闭根和非 DOM 图像文字不在本轮范围。

样式缓存只保存一次读取的 Promise 和 CSSStyleSheet，不持有根引用；清除会移除所有当前连接根上的共享表，异步完成时检查原译文是否仍连接。测试也覆盖清除发生在样式尚未返回的情况。manifest 增加 `assets/content.css` 本地资源声明，便于内容模块读取；没有新增 API 地址、站点权限、运行依赖或远程字体。

## 诊断与缓存

`extraction.scope` 改为 `top-document-open-shadow-dom`，候选数与已有译文数包括组件内符合条件的单元。`openShadowHosts` 现在数已进入的开放宿主，`frameBoundaries` 仍数遇到但未进入的框架。隐藏或明确跳过的子树不会展开统计；没有封闭根计数。它是当前提取结果的说明，不是整页完整覆盖率。

UI、Prompt 版本、预算与缓存协议均保持原样。新发现的正文会改变源列表及其批次语境，相关旧缓存按现有规则不再命中；没有全局清缓存，也没有跨根另开缓存分区。

# v0.17.3：正文提取与遗漏诊断（上一版记录）

在已交付 v0.17.2 源码上修复，直接交付 `just-translate-v0.17.3.zip`，未提交或推送。

用户截图呈现“标题和进度有译文、整段说明与列表没有译文”。没有登录后页面 DOM，不能断言其具体原因。代码审查与失败夹具确认了几类独立的漏提取：`presentation/none` 整棵跳过、误用侧栏标签整棵跳过、选中正文根后丢弃根外内容、flex/grid 下的短段落被判为 UI，以及 `display:contents` 被无盒子判定误伤。

现在扫描主文档，标签和布局只参与候选判断。删除单正文根裁剪与重复叶子扫描，短标签和链接密度过滤保留。flex/grid 中普通叶子块在原子项内回填；通过已有 DOM 标记保持归属，不新增位置 Map。嵌套行内节点也接受明确跳过规则，避免递归过程中用 `textContent` 重新带入被排除的内容。

`presentation/none` 的语义依据见 [W3C ARIA：隐藏语义但保留内容](https://www.w3.org/WAI/ARIA/apg/practices/hiding-semantics/)。

## 提取诊断口径

一次性诊断与验收日志的页面部分都有 `extraction`。调用实际扫描器，以 `snapshot: true` 在复制时重算，不分配翻译 ID，不发起请求，不保留 DOM 引用。只返回固定类别与数字。

| 字段 | 含义 |
| --- | --- |
| `scope` | `top-document-light-dom`，当前能力范围 |
| `completed` | 本次扫描未抛出异常；不表示网页正文已经全部覆盖 |
| `candidateUnits / sourceChars` | 当前过滤后符合条件的单元及字符数，包括已有译文的单元 |
| `existingTranslationUnits` | 当前候选中存在同 hash 译文标记的数量；包括加载或失败标记，不能等同于缓存命中 |
| `skippedElements` | 遍历遇到的首个元素级排除原因，如隐藏、编辑区、显式跳过、用户选择器和非正文标签；不枚举被排除子树的后代 |
| `skippedCandidates` | 文本候选级排除原因，如空白、同文字系统、单词条目、短辅助标签、链接列表和裁剪布局 |
| `frameBoundaries / openShadowHosts` | 遍历时遇到的 iframe/frame 与开放 Shadow DOM 宿主；没有扫描其内部，也不统计封闭根或更深的边界 |
| `invalidSkipSelector` | 当前自定义跳过选择器无效，本次扫描已忽略它 |

这些数字不能当成漏译率。标签误用与组件隔离是两个不同问题：本版修复前者并为后者增加观测，没有修改注入范围、跨根渲染或观察器生命周期。

# v0.17.0：纸色界面与可解释的用量统计（上一版记录）

从已交付的 v0.16.8 继续，直接交付安装包，未提交或推送。安装包根目录是 `manifest.json`，没有额外目录套层。旧维护说明保存在 `MAINTENANCE-v0.16.8.md`。

## 这次解决的问题

预检 prompt 要求 YAML，OpenAI 兼容调用却无条件启用 JSON 模式。这是确定的格式冲突，可能触发 400 降级或无效输出重试；旧日志只有两次请求数字，无法反推上次到底发生了哪一种。本版为预检传递 `responseFormat: text`，翻译仍使用 JSON。

原 `translationRuntime.tokens` 累计了预检与翻译，不适合用来校准翻译阈值。现在只保留 PageSession 内两个阶段桶，页面总量在读取时相加，不另存第三套总计。

| 新字段 | 含义 |
| --- | --- |
| `translationRuntime.tokenScope` | 固定为 `translation`，明确旧字段的新口径 |
| `translationRuntime.tokens` | 仅翻译请求的已知输入、输出 token |
| `translationRuntime.usageIncomplete` | 仅翻译阶段是否有缺失的用量证据 |
| `usageByPhase.translate` | 翻译阶段的 `input / output / incomplete` |
| `usageByPhase.preflight` | 预检阶段的同口径数据 |
| `usageByPhase.total` | 当前页面会话两个阶段之和；任一阶段不完整则总量不完整 |

在语义观测导出中，阶段用量位于 `runtime.usageByPhase`，翻译统计位于 `runtime.translation`；一次性诊断中 `usageByPhase` 与 `translationRuntime` 位于顶层。旧 UI 总 token 仍包括预检。

`incomplete: true` 时，数字是已收到的用量小计，不能当成完整账单。HTTP 错误没有 usage 时不假设它免费；机器翻译接口也不提供 token 用量。新页面会话重新计数，跨页面总账仍不在此快照范围。旧页面的迟到响应不能写进新页面；同一页面被新预检替代的旧画像丢弃，但已知成本仍计入。

## 额外请求从哪里来

每个逻辑批次复用原有 execution 对象，在 `runtime.requestReasons` 中按实际 HTTP 发送计数。生命周期日志的对应事件也保留 `requestReasons`。没有额外的全页请求历史容器；单批仍受原有 9 次请求预算约束。

| 原因 | 对应动作 |
| --- | --- |
| `initial` | 首次发送 |
| `json-format-fallback` | 服务端拒绝 JSON 格式参数后降级 |
| `retry:rate-limit`、`retry:server-error` 等 | 根据前一次失败类别进行实际重试 |
| `missing-items` | 补取缺失或不可用条目 |
| `invalid-response` | 坏 JSON 耗尽重试后缩小批次 |
| `context-length` | 服务端明确拒绝上下文长度后拆分 |
| `source-limit` | 原文超过客户端硬上限后拆分 |
| `boundary-or-length-recovery` | 机器翻译边界或长度恢复；该路径暂不进一步区分两者 |

只安排了退避、还没发送就取消时，不新增请求次数。日志只保存类别和数字，不保存前次错误正文。部分取消与预检缓存写入阶段的异常也保留已有请求统计。

## 观测、导出与缓存

预检提示词要求使用摘要中的原文片段，不将 `encodes and decodes` 擅自改成合成键 `encoding/decoding`。这是定位要求，不锁定义项。`runtime.preflight.sourceCoverage` 使用与观测一致的匹配边界，列出 preferred/risky 的匹配数及 unmatched 列表；范围是当前翻译单元。它既不等于模型 alignment 覆盖率，也不证明这些解释适用于所有出现位置。

覆盖信息从当前单元派生；每个候选仅编译一次匹配表达式，不维护另一套跨批状态。lexical 候选发现没有关闭，也没有新增词干猜测或专词映射。

扩展自身的双语 Markdown 导出补齐标题与列表内原译文之间的段落分隔，并保留 H4–H6 层级。用户贴出的带链接混排文本不符合本扩展导出器的输出结构，不能据此认定 DOM 提取错误。本轮未扩大正文选择器、未放松导航过滤；外部工具复制网页时的混排仍是已知边界。

预检缓存命名空间升级到 `preflight:v2:`，老画像不会被当作满足新契约；各版本合计仍最多 128 条。翻译 `PROMPT_VERSION` 保持 14，没有整体清空翻译缓存。不过首次重新生成的画像若改变了批次语境，原有语境绑定会让对应译文缓存失效；之后相同页面、配置和画像仍能命中。
