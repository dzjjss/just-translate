# v0.16.5：popup 草稿与保存边界

在 v0.16.4 发布包对应工作树上继续，未提交或推送。安装包根目录包含 manifest.json。后台重连和画像缓存的前轮报告保留于 MAINTENANCE-v0.16.3.md。

## 本轮完成的工作

- settings-form.js 独占已确认设置快照、当前表单的服务商身份，以及未显示账户的未保存草稿。当前可见草稿只保留在输入框，切回一个服务商时移除它的离屏草稿副本。
- 未应用状态直接比较草稿与已确认设置，不再维护 dirtyGroups。编辑后撤回原值立即恢复干净；旧保存回执不会清掉后来输入的新草稿。
- 后台 persistSettingsPatch 继续是唯一 storage 写入者和唯一保存队列。popup 不再维护第二条写入队列；按已有 configVersion 接受最新回执，迟到回执不能回退界面快照。失败不修改已确认快照，不清空草稿，不继续启动依赖这次保存的翻译。
- accounts 补丁改为按服务商增量合并。仅提交编辑过的账户和当前选择，不把打开面板时读到的其他账户整份回写。空 accounts 补丁不表示删除账户；本轮没有增加删除账户操作。
- diagnostics.js 负责组合脱敏诊断、复制和按日志水位清除；不保存另一份诊断状态。clipboard 失败不清除；清除失败明确报告已复制但未清空。权限诊断使用保存端点的实际检查结果，不与旧标签状态做逻辑或。
- 页面画像直接从 tabInfo.state.profileYaml 读取，删除 lastProfileYaml 副本。“复制语境到剪贴板”和“复制到页面规则”保持独立。
- API 权限申请集中一处，在第一次 await 前发起；迟到的其他端点权限检查不能修改当前端点的权限判断。面板异步动作在 UI 边界处理失败，保留草稿并提示重试。

翻译及预检规则本轮未修改。src/prompt、翻译调度、正文提取和渲染源码与 v0.16.4 包一致，PROMPT_VERSION 仍为 13；不通过这次维护主动清空已有缓存。

## 状态登记

本轮沿用同一状态扫描脚本，未改检测口径或生命周期分类。详情见 STATE.md 与 state-baseline-v0.16.5.json。

| 移除或迁移 | 现在的所有者与寿命 |
| --- | --- |
| dirtyGroups.model / rules | 无存储；由输入与已保存值比较得出 |
| settingsWriteChain | 无 popup 队列；后台原有 settingsWrites 仍负责串行落盘 |
| lastProfileYaml | 无副本；读取已有页面状态 |
| settings | 迁至 createSettingsForm.saved；面板打开期间的一份已确认快照 |
| modelDraftProviderId | 迁至 createSettingsForm.providerId；标识当前输入框所属服务商 |
| modelDraftAccounts | 改为 createSettingsForm.drafts；只保留尚未保存且当前未显示的账户修改 |
| form | popup 对上述表单管理器的一次初始化引用，不是第二份设置数据 |

删除 6 个旧绑定，登记 4 个新位置，净减少 2 个。将必要的三个绑定迁移到模块不算消灭状态。只读诊断视图模型和传输 DTO 不算新的长期活动状态；静态扫描不是运行时堆快照。

## 验证

源码的 lint 和全部 **312 个用例（19 个测试文件）通过**。新增 14 个用例覆盖输入撤回、保存中新编辑、保存中切换服务商、乱序回执、失败重试、不同账户增量合并、权限检查乱序与点击手势、诊断缺失及清除失败。原画像复制、DOM 时序、后台重启、取消、供应商契约和缓存测试继续通过。

复现：Node >=22.22.2，npm ci 后运行 npm run check；npm run audit:state 输出状态清单。复杂度计算由 test/complexity.test.mjs 使用 ESLint classic complexity；统计包含回调、getter、逻辑短路和可选链，不只计算 if 分支。源行数不含测试和文档。

本轮未重新测覆盖率，不沿用前轮覆盖率冒充本轮结果。Chrome API 使用桩，DOM 使用 jsdom；独立 Node Worker 的销毁重建测试仍不能证明 Chrome 的实际生命周期已经验收。

### 浏览器验收操作

使用包内 test/fixtures/lifecycle.html。在项目目录运行 python -m http.server 8765 --bind 127.0.0.1，打开 http://127.0.0.1:8765/test/fixtures/lifecycle.html；加载当前扩展，选择英语以外的目标语言。

- 翻完基础页，关扩展面板和 worker DevTools，切走五分钟，回来追加一段正文。已有译文应保留，新段落应继续翻译；只有出现 session-reconnected 才有后台回收后重连的证据。
- 刷新并追加长页面内容，开始翻译后中途切走五分钟。返回核对进度和一次性诊断；提前完成只能记录为正常完成，不能当成在途回收通过。
- 开启缓存与整页优先，普通翻译、等待缓存落盘、刷新后再普通翻译。比对预检 hash/reused 和 translation 内的 translateRequestCount/wholePageCacheHit；不要用主动绕过缓存的重翻按钮测试命中。
- 翻译途中停止，等待后台空闲后返回；旧任务不应自行复活，手动开始应建立新会话。
